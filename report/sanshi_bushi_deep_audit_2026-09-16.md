### 1.1 奇门遁甲（Qimen Dunjia）

#### (1) 盘法实现：转盘法 vs 飞盘法
- **转盘法（主流开源与 shushu 的共同选择）**：
  * `kentang2017/kinqimen`：采用纯转盘。九星序为 `蓬任沖輔英禽柱心`（绕八宫顺时针转，天禽寄芮），八门序为 `休生傷杜景死驚開`，八神为 `符蛇陰六白玄地天`。星随值符干转，门随值使时转，神随值符星转。
  * `perfhelf/bigfishmarquis-qimen`：自建 `shijia.ts`，定义 `PALACE_CLOCKWISE = [1, 8, 3, 4, 9, 2, 7, 6]`（坎艮震巽离坤兑乾），九星转盘序 `STAR_SEQUENCE = ['天心', '天蓬', '天任', '天冲', '天辅', '天英', '天芮', '天柱']`，八门转盘序 `GATE_SEQUENCE = ['休门', '生门', '伤门', '杜门', '景门', '死门', '惊门', '开门']`。天盘九星沿方位环旋转 `step` 步。
  * `D:\shushu`（`l3_qimen.py`）：方位环 `RING = [1, 8, 3, 4, 9, 2, 7, 6]`，值符星按方位环转至时干落宫（天禽星随天芮星转，并携中宫地盘干同显）；值使门沿洛书数步求落宫后，门圈整体平移。
- **飞盘法（鸣法/陶真人体系）**：
  * 开源生态中纯正飞盘法极为罕见。多数开源库（包括 kinqimen、bigfishmarquis-qimen）名义上提供“奇门”，实则 100% 均为转盘法。飞盘奇门要求九星飞九宫（中五天禽独占一宫，不寄坤）、九门飞九宫（八门加中宫飞杜门/中休门）、九神顺飞九宫（值符、腾蛇、太阴、六合、勾陈、朱雀、九地、九天、直符）。开源社区目前尚无高质量具备测试用例的飞盘实现。

#### (2) 定局算法差异：拆补法 vs 置闰法 vs 茅山法
- **拆补法（Chai Bu）**：
  * 原理：节气时刻交节即换该节气，以日干支符头（甲己日）确定上中下元（子午卯酉上元、寅申巳亥中元、辰戌丑未下元）。允许“残元补局”（节气未到但符头已到，或节气已到但符头未到）。
  * `bigfishmarquis-qimen`（`chaibuquju.ts`）：往前找最近甲己符头，直接按地支定三元，结合当前节气局数表查局。
  * `D:\shushu`（`l3_qimen.py`）：以真太阳时所属节气为基准，找节气交时刻后首个甲己符头日 $F$，若当前日 $D < F$ 为残日，取 $(F_{\text{yuan}} - 1) \bmod 3$（经易安居实测校准）；$D \ge F$ 则顺推。
- **置闰法（Zhi Run）**：
  * 原理：严格遵守符头统辖 15 天（一气三元），因太阳公转节气（约15.218天）与符头周期（15天）脱节，产生“超神”（符头先到节气）与“接气”（节气先到符头）。当超神达到 9 天以上时，在芒种或大雪之后置闰一气（重演芒种或大雪三元 15 天），使符头与节气重新同步。
  * `bigfishmarquis-qimen`（`zhirun.ts`）：实现完整优雅。先找上元符头（甲子/己卯/甲午/己酉），计算 `chaoShenDays = findUpperYuanFuTouOffset(jieQiDayGz)`；当 `chaoShenDays > 9` 且节气为芒种或大雪时触发置闰，三元周期扩展为 30 天；若符头超出周期则切换至下一节气。
  * `kentang2017/kinqimen`（`config.py`）：通过大量启发式条件硬编码（如判断 `lunar_month in ["腊月", "冬月"]`、`solar_month >= 9`、`lunar_day < 15`），分支繁杂且缺乏文献推导统一性。
  * `D:\shushu`（`config_engine.py`）：在 `_qimen_dingju_zhirun` 中支持符头三元定局与超神接气扩展。
- **茅山法（Mao Shan）**：
  * 原理：彻底废弃干支符头，纯依天文交节时刻起局。交节时刻一到立即进入该节气上元；每过 60 时辰（5 天/120小时）换一元（交节后 0~5天上元、5~10天中元、10~15天下元）。
  * `bigfishmarquis-qimen`（`maoshan.ts`）：根据交节后经过小时数 `elapsedHours`，`Math.floor(elapsedHours / 120)` 直接分为 0(上)、1(中)、2(下)元。
  * `D:\shushu`（`config_engine.py`）：`_qimen_dingju_maoshan` 算法相同：`days_diff = (ts.date() - d0).days`，0~4天上元、5~9天中元、10天以上下元。

#### (3) 关键算法审查与开源严重缺陷曝光
在审查 `xiongdun8/liuyao` 的 `main.py` 源码时，发现其**旬空计算函数 `get_xunkong` 存在灾难级逻辑 Bug**：
```python
# xiongdun8/liuyao/main.py 源码:
def get_xunkong(day_ganzhi):
    day_gan = day_ganzhi[0]
    day_zhi = day_ganzhi[1]
    day_gan_idx = GAN_ORDER.index(day_gan)
    day_zhi_idx = ZHI_ORDER.index(day_zhi)
    day_total_idx = day_gan_idx * 12 + day_zhi_idx  # <--- 严重错误！
    ...
    for i in range(len(XUN_START)):
        ...
        start_total_idx = start_gan_idx * 12 + start_zhi_idx
        end_total_idx = end_gan_idx * 12 + end_zhi_idx
        if start_total_idx <= day_total_idx <= end_total_idx:
            return XUN_KONG[XUN_START[i]]
```
- **Bug 机制剖析**：六十甲子干支循环并非按 `gan_idx * 12 + zhi_idx` 线性递增！
  例如：甲子为 $0 \times 12 + 0 = 0$，癸酉为 $9 \times 12 + 9 = 117$。第一旬的区间被算成了 $[0, 117]$！
  而第二旬甲戌日的索引是 $0 \times 12 + 10 = 10$，它落在 $[0, 117]$ 之内！
  实测运行导致：**甲戌日、乙亥日（本应属甲戌旬，申酉空）全被误判为甲子旬（戌亥空）**！六十甲子中超过一半的干支在该函数中得到错误的旬空！
- **shushu 的正确实现**：
  `config_engine.py` 采用严格数论公式：`[ZHI[(z_i - g_i + 10) % 12], ZHI[(z_i - g_i + 11) % 12]]`，数学上保证 $100\%$ 精确，无任何区间错位问题。

### 1.5 梅花易数（Meihua Yishu）

#### (1) 起卦法与计算链
- **时间起卦**：
  * `muyen/meihua-yishu`（`meihua_calc.py`）：以农历时间起卦，上卦 = (年支数 + 农历月 + 农历日) % 8，下卦 = (年支数 + 农历月 + 农历日 + 时辰数) % 8，动爻 = (总数) % 6。
  * `D:\shushu`（`l3_meihua.py`）：规则完全相同，且明确界定了年支取法：节气干支年支（立春换年，对齐邵雍观梅占辰年口径）并记录了换算链（`chain`）。
- **报数起卦**：
  * `muyen/meihua-yishu`：两数取 `(num1+num2) % 6`，三数取 `(num1+num2+num3) % 6`，并在注释中严正考证指出：“三数时只取 num3 是常见今人简法，非原书之法”。
  * `D:\shushu`（`l3_meihua.py`）：主表提供双数与三数标准起卦，同时以 `variant="add_hour"` 支持易运盘 oracle 实测的“动爻加时辰派”，并在 `alt` 中完整保留流派异文说明。

#### (2) 卦象展开与体用生克五态
