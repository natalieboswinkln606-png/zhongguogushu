## 三段锚点声明

| 锚点段 | 定义源 | 精度 |

## 容差与判定字段

- `source_tolerance`：张培瑜 ±1 时辰（2 小时）；紫台/港台历表 1 分钟（分钟级）。
- `compare_threshold`：对拍差异判类阈值——节气时刻差 > 1 分钟判「算法分歧」；≤ 1 分钟判一致；日干支等离散量不允许容差，非一致即差异。

## 校核与历法规则

- 1948-1951（表范围起点附近）边界段互校（原定陈垣《二十史朔闰表》与张培瑜互校）降级为可选：节气表录入源 = 「M1 节气策略裁决」节声明（紫台国标仅口径定义源，附录 A 无逐年时刻），有港台历表则核、无则不做，不阻塞录入；日干支已由 M0 与 lunar-python 全量对拍验证，无需互校。
- 时区：UTC+8 固定录入，不允许混入其他时区数据。
- 1900 年前日期声明为儒略历（旧历），gen_ganzhi.py 明确不处理儒略历（只做格里高利 1900-2100）。
- 均时差锚点：《中国天文年历》逐年表 + NOAA 独立计算互校，两者差 > 1 分钟入仲裁；真太阳时换算只用这两源，不用第三方推导值。

## 约定语义

- 换日界 = 真太阳时子正（0:00 子正换日；lunar-python 默认 23:00 子初换日，两者差异归「算法分歧」类单列，不入主数据）。
- 月将宫界 = 黄经 30° 整数倍过宫，≡ 中气（十二中气即十二宫界）。
- 干支编号：甲=0…癸=9、子=0…亥=11，甲子=0。与 rules.py 的 gan_idx/zhi_idx 一致，成文固定，防实现漂移。

### 真太阳时换日界案例（拉萨 91°E）

北京时 0:30 出生（120°E 基准）→ 拉萨（91°E）真太阳时 = 0:30 − 4×(120−91) 分 ≈ 前一日 22:34 → 子正换日判为**前一日亥时**。日柱与时柱必须同轨真太阳时：换日判定与时辰归属用同一时标，不得日柱用北京时间、时柱用真太阳时。

## 公历与农历转换

- 转换触点声明：输入 = 公历（北京时间 UTC+8）。判定层（年柱/月柱）= 只依赖 solar_terms 节气表，不经过农历（八字月柱无闰月概念，闰月出生按节气归月建，12 节固定对应 12 月建）；显示层农历日期（L3 紫微排盘用）= 依赖朔日表 + 闰月判定（无中气月置闰，依赖 solar_terms 表中气时刻）；朔日表录入列为 L3 前置、非 M1 阻塞（shuowang 空模板已建）。
- 年界双口径成文区分：术数年柱/生肖 = 立春（已裁决）；民俗农历年 = 正月初一。两套口径互不顶替、不得混用（正月初一至立春之间出生的日子，两口径归属不同年）。
- 录入时区契约：节气/朔望时刻一律 UTC+8 北京时间标注入库，禁止 UTC；数据源时区须逐源核实后录入（防 8 小时错位）。
- 历法体制：1900-2100 全格里高利历（1900 前儒略历声明保留，不扩展）。

## M1 输入语义

- 输入 = 北京时间（UTC+8）+ 地点经度（东经为正）。真太阳时 = 北京时间 + 4×(经度−120) 分 + 均时差（NOAA 公式，幅度 ±16 分内）。
- 修正幅度可能使真太阳时日期落在 ganzhi_days 表（1900-01-01 至 2100-12-31）之外：按中国境内经度 73°E–135°E 折算——西部经度下北京时间 1949-01-01 0:00–3:30 输入 → 真太阳时落 1948 年（东经 91°：−116 分−EOT −16 分 ≈ −132 分），故下界取 03:30 起；东部经度下 2100-12-31 晚间输入 → 真太阳时落 2101 年。
- M1 有效输入范围声明（保守收窄，宁紧勿松）：**北京时间 1949-01-01 03:30 至 2100-12-31 20:30**。越界返回 `out_of_range`，不静默截断、不做表头/表尾夹取。

## M1 节气策略裁决

- solar_terms 表为唯一运行期权威。表范围：**1948–2101 共 3696 行（154 年 × 24 节气）**，其中主表语义 1949–2100（3648 行）；前导年 1948 与后导年 2101 各 24 行为判定辅助行（年柱/月柱判定需「最近上一节」时刻：1949-01 输入需 1948-12 大雪，2100-12 末输入需 2101-01 小寒）。表录满（1948–2101）前，任何依赖节气时刻的判定（月界、年界立春）一律返回 `anchor_missing` 拒绝判定；**禁止回退用 lunar-python 计算值顶替**（lunar-python 仅作录入对拍 oracle，不作权威，与三段锚点声明一致）。
- 数据源声明（纯自动+官方互校，2026-08-15 用户裁决）：
  1. 日期层锚定：HKO 官方公历农历对照表逐年 txt（1901–2100 覆盖，UTC+8），1948–2100 全量。
  2. 时刻层互校：HKO 官方分钟级 2015–2028（年历内嵌/XML/PDF/交互页）共 336 锚点，与 lunar-python 差 >1 分钟入仲裁（沿用 compare_threshold）。
  3. 时刻层实现：lunar-python getJieQiTable() 秒级（东八区），属「库（实现源）」角色——对拍 oracle + 生成工具，**不作运行期权威**；运行期只读 solar_terms 表。
  4. 无官方源段：2101 年 24 行（超 HKO 范围）标注「算法值（lunar-python，无官方锚点）」；纸本《大众万年历（1901-2100）》（紫台编，时辰级精度）5% 年抽查挂起（13.5 元购书，待书到位后执行，结果入仲裁记录）。
- 均时差：NOAA 均时差算法为公开公式，可编程实现（不属于"库"）。EOT 每日表生成+《中国天文年历》抽年互校：列为待办（需《中国天文年历》数据源），当前运行时 NOAA 公式为唯一实现，无锚点互校前不生成冗余 EOT 表（先锚点后断言）。

## 角色与剔除

- 三角色：实现者（填数据）、复核者（独立核验，不参与录入）、审计者（抽查仲裁记录）。
- 剔除三态：
  1. 拒绝（reject）：数据确认错误，不入库，留 arbitration_log 记录；
  2. alt 标注（alt）：异文并存（如覆灯火/佛灯火），标 source_ref 注释，主表取一、异文进 whitelist；
  3. schema 缺省（default）：字段无值用 schema 缺省，不写空造值。

## 交付快照（冻结锁，I-3）

- 生成：里程碑完成时在仓库根执行 `git ls-files | xargs sha256sum > SHA256SUMS.txt`，首行记 `# generated: <ISO8601 时间戳>`；无 git 环境时改用 `sha256sum data/* docs/* report/* *.py LICENSE`（Windows 单文件：`certutil -hashfile <file> SHA256`）。清单覆盖全部数据/代码/文档。SHA256SUMS 不含自身（标准做法），GPG 签名后闭环。
- 校验：`sha256sum -c SHA256SUMS.txt`。
- 签名：GPG 对清单签名（`gpg --detach-sign --armor SHA256SUMS.txt`），公钥指纹公布于 README；GPG 未配置前清单标注 `# signature: pending`，禁止借「待定」跳过清单生成。
- 冻结锁 = 输出契约，不是数值：锁的是 Rule-ID 语义、JSON 字段格式、换日界/月将宫界等判定规则。数值随勘误合法演化；规则变更须升版本（vN → vN+1）。
- 快照时机：每个 M 里程碑完成时快照一次（M0 已冻结）。

## 勘误补丁通道（I-3）

1. 发现错误 → 升数据版本号 → 重算 → 重签 SHA256SUMS.txt → 根哈希更新。
2. 影响报表：受影响行清单 + 新旧值对照 + 差异原因，存 report/errata/<版本号>.md。
3. 禁止静默修改已冻结数据：一切变更必须有 errata 记录，对应 git commit 可溯源。

## 运行时仲裁契约（Runtime Arbitration，I-8）

- 冻结快照是基线基准、默认引用，但不是绝对真理：后续所有运行/对拍验证不得仅凭冻结快照作「百分百确认」，快照只是当前置信最高的参考，不构成判决书。
- 任何计算输出与快照不一致时，禁止默认快照正确，也禁止默认实现正确：两侧一律进入待裁决状态，不得静默取用任一侧结果继续。
- 不一致必须启动重新仲裁流程，至少两种独立源交叉验证：官方历表（HKO/紫台等）、星历计算（skyfield DE440 等）、第三方万年历，据以确定哪方正确。
- 仲裁结果处理：若快照错 → 更新数据表并重签快照（走勘误补丁通道）+ 追加 arbitration_log.csv；若实现错 → 修代码；两者均记录原因与证据。
- 适用范围：L3 及以后所有术种层。

## 白名单增补流程（F-2）

事后增补白名单条目必须三步，缺一不可：
1. **3 源仲裁**：原卷 + 第二独立来源 + 第三独立来源一致（口径同转录协议）；
2. **全量回归**：compare.py + validate.py + assert_tables.py 全过；
3. **审计记录**：复核者确认 + 审计者签字，写 arbitration_log（decision=alt）。
禁止单方追认：实现者不得独自增补白名单。

## 转录协议（I-6）

- 转录源：纸本扫描影印件为唯一转录源，不用网传电子版。
- 转录者分离：实现者录入、复核者核验，两者非同人；复核者不参与录入（沿用三角色）。
- 全量单录 + 5-10% 抽样双录：全部数据单转录一遍；另抽 5-10% 样本由第二人独立转录，比对一致才通过该批次。
- 仲裁链三步：① 重读原卷（原始扫描件）→ ② 第三独立来源 → ③ 裁定留档。各步结果分别记入 arbitration_log：chain_step（重读原卷/第三来源/裁定）、original_source、third_source。

## 卦例规则层锚定（I-7）
